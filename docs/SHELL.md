# LoOS shell (`src/shell`, library `loos_shell`)

Pure C11, no allocation, no OS calls. The caller owns the framebuffer and feeds input events, so the same code
runs in the real compositor process and in host tests (`ctest -R shell`). Palette comes from `branding/brand.h`.

## Layers

| Layer | Files | What it does |
|---|---|---|
| Drawing | `draw.c`, `font8x16.c` | rects, rounded rects, alpha blend, 8x16 bitmap text (generated by `scripts/gen_font.py` from Noto Sans Mono, OFL), damage list, themes (dark / light / high contrast) |
| Compositor (U0) | `compositor.c` | window stack, z-order (topmost class), hit zones (title, caption buttons, 8 resize edges), drag/resize/maximize, focus, per-window event queue, damage-driven repaint, overlays, cursor |
| Window manager (U2) | `wm.c` | snap layouts (halves, quarters, thirds, 2/3), drag-to-edge preview, Super+arrow/digit keys, 8 virtual desktops, multi-monitor + per-window DPI (`EV_DPI_CHANGED`), focus-follows-mouse, master/stack tiling |
| Taskbar + launcher (U1) | `taskbar.c`, `launcher.c`, `inventory.c` | window buttons, network LED + hard "no network" switch, clock, Alt+Tab, Super / Ctrl+Space; fuzzy search over apps, files and settings (local only) |
| Toolkit | `ui.c`, `apphost.c` | immediate-mode widgets (button, toggle, radio, text field, tabs, list, slider, progress), Tab focus ring, Enter/Space activation, accessibility registry (`ui_a11y_dump`), `appwin_*` hosts a frame function in a compositor window |
| Backend contract | `backend.h`, `backend_mem.c` | the only way shell code reaches the OS: NetMonitor/Firewall, Perms, Fs, Ps, local config. `backend_mem` is the in-process reference |
| Apps | `settings.c` (U3), `filemgr.c`, `taskmon.c` (U4), `compat_console.c` (U5) | privacy control center, file manager, task monitor, compatibility console |
| Session | `session.c` | local accounts (PBKDF2-HMAC-SHA256, per-account salt, exponential lockout), session state machine, login/lock screen, first-run account creation |
| Privacy services | `perms.c`, `notify.c` | per-app permission broker (nothing granted by default, allow-once is session-only, in-use indicators), notification center with permission gate, rate limit, DND |

## Rendering (resolution independent)

* **Logical pixels.** Apps, overlays (taskbar, launcher, notifications, prompts) and the installer lay out in *logical* px;
  `shell_fb.scale` (percent) maps them to device px inside every drawing primitive, so a 1920x1080 screen at 100% and a
  3840x2160 screen at 200% show the same layout, equally sharp. `desktop_auto_scale()` picks 100/150/200 by resolution; the
  Settings app and `scale=NNN` on the kernel command line override it. Client surfaces are device resolution.
* **Text.** Inter outlines (`crates/loos-shell/src/font_data.rs`) are rasterised on demand by `raster.rs` (exact-area coverage, integer only, usable in
  the kernel) at the exact device size and a quarter-pixel phase, cached by `font.rs` (both in `crates/loos-shell`). Proportional layout (`shell_text_width`,
  `shell_ellipsize`, caret mapping) is measured in logical px; UTF-8 is decoded, Latin-1 plus a few symbols are included.
* **Shapes.** Rounded rects, rings and circles are anti-aliased by distance coverage; windows have soft distance-based shadows
  and rounded corners (client surfaces are masked in the corners); the cursor is an anti-aliased polygon; the wallpaper is a
  dithered gradient with two soft glows derived from the theme.
* **Toolkit + theme.** `ui.rs` is the immediate-mode widget toolkit (focus, clipping, accessibility tree); `theme.rs`
  resolves presets, HSL accents, per-token overrides and the WCAG contrast guard, and exports/imports the `ui.*` text form.
* **Taskbar + Start.** `taskbar.rs` / `launcher.rs` own the bar, tray, Quick Settings/calendar flyouts and Start
  (fuzzy local search only: no web results, feed or ads); `notify.rs` owns the notification center; `inventory.rs` the app list.
* **Compositor + WM.** `crates/loos-shell/src/{compositor,wm}.rs` own window state, z-order, focus, hit testing,
  damaged-region painting with occlusion culling, wallpaper, chrome, cursor and the WM (snap, desktops, tiling).
* **Desktop object.** `desktop.c` is the whole shell as one portable object (used by the kernel and by `tools/shell/shell_snap`,
  which renders any resolution/scale to a PPM for review and for the resolution test).

## Rules the code enforces

- No UI action generates network traffic. The network LED and the hard switch read/write the same backend state the
  Settings firewall page uses, so they cannot disagree.
- Permissions: ASK until the user decides; floods of requests fail closed; revoking an app also drops its in-use indicators.
- Updates are opt-in and the mirror address defaults to empty: no address is built in.
- Passwords are never stored or logged in clear; typed password buffers are wiped after each attempt; the account store
  refuses to create a hash without a caller-supplied or CSPRNG salt.

## Contract for backend implementers

`shell_backend` in `backend.h`. Every entry takes the backend `user` pointer first. Real implementations map onto:
`net_query`/`fw_*` -> NetMonitor + Firewall, `perm_*` -> Perms, `fs_*` -> Fs, `ps_*` -> Ps.snapshot, `cfg_*` -> registry hive.
`backend_mem_save/load` shows the on-disk text format used until the registry service exists.

`shell.compositor_test`, `taskbar_test`, `wm_test`, `ui_test`, `settings_test`, `apps_test`, `a11y_test`,

## Installer and login

`installer.c` is a six-step wizard (welcome, disk, account, privacy, review, progress) with strict validation (RFC 1123 host
names, `[a-z][a-z0-9_-]*` user names, password policy) and private defaults (network blocked, updates off). It talks to a
`shell_inst_backend`; the kernel's backend (`src/kernel/boot/install.c`) installs a BIOS (MBR) or UEFI (GPT + FAT32 ESP) layout to any
ATA/AHCI/NVMe disk, formats the data partition as btrfs, stores the account as a salted PBKDF2 hash
(iterations calibrated to ~0.3 s on the machine) in the config area, and verifies everything by reading it back.
`session.c`'s login screen (same gradient backdrop as the installer via `ui_backdrop`) then guards the installed system. See [BOOT.md](BOOT.md).

## Not done yet

Per-monitor DPI scaling of fonts (chrome metrics scale, glyphs do not), IME/UIA bridge to external readers (the
registry in `ui.c` is the data source), thumbnails/preview panes and tabs in the file manager, search index
persistence for the launcher. Browser: JavaScript, full CSS layout, images and a native network stack (the
Firefox/Gecko port is planned in [BROWSER.md](BROWSER.md); the current app is a local-first shell, HTML/CSS
subset and a development-only QEMU web bridge).

See [BROWSER.md](BROWSER.md) |

Logic is safe Rust with unit tests (`cargo test -p loos-shell`); the `loos_*_frame` functions draw
through the C toolkit until it is ported. Files now have contents: `shell_backend.fs_read/fs_write`
(in-memory backend: 16 files x 16 KiB). The Windows `.exe` builds in `apps/` remain for the PE
compatibility corpus; they run natively once the process loader exists. The browser is covered by
`tests/shell/browser_test.c` (`ctest -R shell.browser_test`).
